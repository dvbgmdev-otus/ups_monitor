# API приложения

## 1. Назначение

Приложение предоставляет интерфейс командной строки для запуска мониторинга одного ИБП. Входными данными являются параметры командной строки и файл спецификаций поддерживаемых моделей ИБП. Результаты мониторинга выводятся в стандартный поток вывода.

## 2. Интерфейс командной строки

### 2.1. Формат запуска

```text
ups_monitor [--ip <IPv4>] [--port <номер>]
ups_monitor --help
```

Пример:

```text
ups_monitor --ip 192.168.1.10 --port 161
```

### 2.2. Аргументы

| Аргумент | Обязательный | Значение по умолчанию | Назначение |
|---|---:|---|---|
| `--ip <IPv4>` | Нет | `127.0.0.1` | IPv4-адрес ИБП |
| `--port <номер>` | Нет | `161` | UDP-порт SNMP-агента в диапазоне от `1` до `65535` |
| `--help` | Нет | — | Вывести справку и завершить работу |

Неизвестный аргумент, отсутствие значения после `--ip` или `--port`, некорректный IPv4-адрес либо недопустимый номер порта считаются ошибкой запуска.

## 3. Файл спецификаций моделей ИБП

### 3.1. Назначение и расположение

Файл спецификаций содержит данные, необходимые для определения модели ИБП, опроса её параметров и проверки полученных значений. Приложение загружает файл `config/ups_model_spec.ini`. Путь определяется относительно каталога исполняемого файла и не передаётся через командную строку.

Файл имеет формат INI. Каждая секция описывает одну модель ИБП, а имя секции является её уникальным идентификатором.

### 3.2. Поля спецификации модели

| Поле | Назначение |
|---|---|
| `modelName` | Название модели, которое должен содержать ответ ИБП |
| `modelName.oid` | OID, по которому запрашивается название модели |
| `<parameter>.oid` | OID контролируемого параметра |
| `<parameter>.normal` | Допустимый диапазон или перечень значений параметра |
| `outputStatus.bypass` | Перечень значений `outputStatus`, соответствующих включённому байпасу |

Для обычного контролируемого параметра обязательны поля `oid` и `normal`. Для `outputStatus` обязательны поля `oid` и `bypass`.

Поддерживаются следующие имена параметров:

| Имя параметра | Назначение |
|---|---|
| `batteryStatus` | Состояние батареи |
| `chargeRemaining` | Уровень заряда батареи |
| `batteryTemp` | Температура батареи |
| `inputFreq` | Входная частота |
| `inputVoltage` | Входное напряжение |
| `outputVoltage` | Выходное напряжение |
| `outputStatus` | Режим работы выходной цепи |

### 3.3. Формат критериев

Допустимый диапазон задаётся двумя целыми неотрицательными значениями через `..`:

```ini
inputVoltage.normal = 200..259
```

Перечень допустимых значений задаётся целыми неотрицательными значениями через запятую:

```ini
batteryStatus.normal = 2
outputStatus.bypass = 6,9,10
```

Минимальное значение диапазона не должно превышать максимальное. Пустые и нечисловые значения не допускаются.

Критерии задаются в единицах измерения, используемых соответствующим OID. Например, входная частота может передаваться в десятых долях герца, поэтому диапазон от `40` до `60 Гц` записывается как `400..600`.

### 3.4. Пример спецификации

```ini
[APC_RT_2000_XL]

modelName = Smart-UPS RT 2000 XL
modelName.oid = 1.3.6.1.4.1.318.1.1.1.1.1.1.0

batteryStatus.oid = 1.3.6.1.4.1.318.1.1.1.2.1.1.0
batteryStatus.normal = 2

chargeRemaining.oid = 1.3.6.1.4.1.318.1.1.1.2.2.1.0
chargeRemaining.normal = 30..100

batteryTemp.oid = 1.3.6.1.4.1.318.1.1.1.2.2.2.0
batteryTemp.normal = 0..50

inputFreq.oid = 1.3.6.1.4.1.318.1.1.1.3.3.4.0
inputFreq.normal = 400..600

inputVoltage.oid = 1.3.6.1.4.1.318.1.1.1.3.2.1.0
inputVoltage.normal = 200..259

outputVoltage.oid = 1.3.6.1.4.1.318.1.1.1.4.2.1.0
outputVoltage.normal = 200..259

outputStatus.oid = 1.3.6.1.4.1.318.1.1.1.4.1.1
outputStatus.bypass = 6,9,10
```

Если файл спецификаций отсутствует, мониторинг не запускается. Некорректные секции не используются. Если определить модель ИБП не удалось, мониторинг не запускается.

## 4. Результаты работы

После определения модели приложение выводит сообщение с её названием:

```text
2026-07-15 14:25:30 [UPS] detected model="Smart-UPS RT 2000 XL"
```

После каждого завершённого цикла опроса приложение выводит общее состояние ИБП и битовую маску отклонений:

```text
<дата и время> [UPS] status=<состояние> deviations=<маска>
```

Дата и время соответствуют моменту формирования состояния и выводятся по локальному времени в формате `YYYY-MM-DD HH:MM:SS`. Допустимые состояния: `OK`, `WARNING`, `FAILURE`, `NO_INFO`. Маска отклонений выводится как восьмизначное шестнадцатеричное число.

Примеры:

```text
2026-07-15 14:25:33 [UPS] status=OK deviations=0x00000000
2026-07-15 14:25:43 [UPS] status=WARNING deviations=0x00000042
2026-07-15 14:25:53 [UPS] status=FAILURE deviations=0x00000020
2026-07-15 14:26:03 [UPS] status=NO_INFO deviations=0x00000000
```

## 5. Завершение работы

После успешного запуска приложение работает непрерывно. Пользователь может остановить его сочетанием клавиш `Ctrl+C`. При получении сигнала прерывания приложение должно остановить цикл опроса, дождаться завершения фоновой операции и закрыть UDP-сокет.

После завершения приложение возвращает операционной системе один из следующих кодов:

| Код | Значение |
|---:|---|
| `0` | Успешное завершение после вывода справки или штатной остановки мониторинга через `Ctrl+C` |
| `1` | Ошибка аргументов командной строки или инициализации приложения |

Ошибки получения параметров во время мониторинга учитываются при формировании состояний `WARNING`, `FAILURE` и `NO_INFO`, но не завершают приложение и не влияют на код его завершения.

Ошибки запуска и инициализации выводятся в стандартный поток ошибок `stderr`:

```text
error: <описание>
```
